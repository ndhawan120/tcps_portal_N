# TCPS Professional Development Portal

A role-based internal professional development portal for TC Professional Services. The application supports employee ACCA/PER tracking, manager review workflows, organisation administration, reporting, announcements and profile management.

## Stack

- Next.js 14 / App Router
- React 18 + TypeScript
- Tailwind CSS
- Supabase Authentication, PostgreSQL and Row Level Security
- Vercel hosting

## Role structure

### Employee
- Dashboard — personal summary and next actions
- Exam / PER — canonical learning and PER workspace
- Documents — PER evidence notes and supporting information
- Updates
- Profile — personal professional information, including the employee-maintained PER Objective Number

### Manager
- Dashboard — personal/team summary and management shortcuts
- Exam / PER — development workspace
- Team — direct-report progress and action queue
- Approvals — PER submissions requiring manager action
- Reports — analysis and KPIs for assigned employees
- Updates
- Profile

### Admin
- Dashboard — organisation summary and operational shortcuts
- Exam / PER — development workspace
- Team — workforce progress and relationships
- People — complete office directory: employees, managers and admins
- Approvals — organisation-wide approval workflow
- Reports — organisation-wide analytics and KPIs
- Admin — administration/configuration hub
  - Roles & Access — managed business role names and active departments
  - Branding — portal branding
- Updates
- Profile

## Profile PER Objective Number

Each employee profile contains an **Employee-maintained PER Objective Number** field. The employee can enter or update this reference from their own Profile. Managers and admins cannot edit this field from the employee profile; they can view it when opening an authorised employee record from People/Employees or Team.

This field is deliberately separate from the detailed **PER Objectives** workflow. It is a profile-level reference, while Exam / PER remains the source of truth for objective records, evidence, status and approvals.

The database column is `profiles.per_objective_number` and is nullable so existing employees can leave it blank until they enter their reference.

## Tab responsibilities

- **Dashboard:** summary and next actions. It owns the high-level overview and must not duplicate the Admin configuration hub.
- **Team:** operational workforce/progress and actions. Managers see direct reports; admins see active workforce.
- **People:** source of truth for office people records and people actions.
- **Approvals:** source of truth for PER approval workflow.
- **Reports:** analysis, rates, distributions and KPI interpretation.
- **Admin:** configuration and administration entry points, not another copy of the Dashboard.
- **Roles & Access:** nested under Admin rather than a separate primary navigation item.
- **Documents:** currently PER evidence notes; not yet a general-purpose file-management system.
- **Profile:** personal information and the employee-maintained PER Objective Number. Detailed PER progress remains in Exam / PER.

## Internal linking principles

- Employee records always link to canonical `/employees/{profile_slug}` URLs, never UUID URLs.
- Dashboard summaries link to their source/action page.
- Manager: Dashboard → Team → Employee profile → Approvals or Reports.
- Admin: Dashboard → Team/People/Approvals/Reports; Admin → Roles & Access/Branding.
- Reports links back to Team, People or Approvals when action is required.
- Profile links to Exam / PER for detailed development work.

## PER source of truth

The portal keeps **22 PER objectives** as the source-of-truth objective total. Detailed objective records, evidence, progress and approvals remain in Exam / PER. The profile-level PER Objective Number is only a reference supplied by the employee and is not used as a replacement for the detailed PER records.

## Departments and controlled options

Departments are managed through Admin → Roles & Access. Profile, Add User and admin profile-edit forms use the active `departments` table rather than independent hard-coded lists. Existing inactive/legacy values remain visible only when already assigned so they can be migrated safely.

Other security-sensitive profile fields such as role and account status remain controlled by administrative workflows rather than being editable from a normal employee profile.

## Permissions

Navigation is not an authorization boundary. Role-sensitive pages and API handlers validate the authenticated active profile, and Supabase RLS remains the database-level boundary.

| Area | Employee | Manager | Admin |
|---|---:|---:|---:|

| Exam / PER | Own | Development context | Development context |
| Documents | Own | — | — |
| Team | — | Direct reports | Active workforce |
| People | — | Scoped people access | Full office directory |
| Approvals | — | Assigned employees | Organisation |
| Reports | — | Assigned employees | Organisation |
| Admin | — | — | Full |

## Documents status

The current Documents area displays PER evidence notes stored with objectives. It does not yet represent full uploaded-file management. A future file-management implementation should add Supabase Storage, document metadata, access rules, upload/delete behavior and retention rules deliberately.

## Deployment

Production is hosted on Vercel and connected to this repository.

Recommended flow:

1. Create a backup branch before structural changes.
2. Work on a feature branch.
3. Run `npm run check`.
4. Review the Vercel preview.
5. Verify employee, manager and admin journeys.
6. Merge to `main` only when the preview is healthy.
7. Confirm production after deployment.

Production URL: `https://tcps-portal-n.vercel.app`

## Troubleshooting

### Old UUID employee URLs

Never generate `/employee/{uuid}` internally. Employee directory and Team links must use `/employees/{profile_slug}`. Middleware may keep the old route only as a compatibility redirect for bookmarks or external links.

### Vercel module-not-found errors

Check import path and filename casing. Vercel builds on Linux, so imports must match filenames exactly.

### Unexpected role access

Check `components/Nav.tsx`, `middleware.ts`, the affected page and its API handler. Navigation visibility is never authorization by itself.

### Material Symbols appear as text

Confirm the Material Symbols font import and `.material-symbols-outlined` styling remain present before changing navigation markup.
