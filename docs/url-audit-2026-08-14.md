# Employee URL audit — 2026-08-14

## Findings

The employee URL flow had two inconsistencies:

1. The main employee directory already preferred `profile_slug`, but some manager/admin reporting links still used the legacy UUID-based `/employee/{uuid}` path.
2. The canonical employee detail route is `/employees/{identifier}`, while `/employee/{identifier}` remains a legacy compatibility route.

## Correct canonical route

`/employees/{profile_slug}`

Examples:

- `/employees/jane-doe`
- `/employees/samuel-king`

UUIDs remain accepted internally for backwards compatibility, but new UI links should not generate them.

## Fix applied

- Reporting/team links now use `profile_slug` when available.
- A deterministic name-slug fallback is used when an existing profile has no slug.
- The canonical plural employee detail route continues to accept both UUID and slug identifiers.
- The legacy singular employee route remains available for old bookmarks and UUID links.

## Validation target

The supplied UUID URL should remain backwards-compatible, while newly generated links should use the employee's friendly slug.
